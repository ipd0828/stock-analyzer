# 📊 Stock Analyzer — автоматизированная система анализа акций

**Stock Analyzer** — это автоматизированная система фундаментального анализа, прогнозирования цен на основе машинного обучения, сентимент-анализа новостей с помощью большой языковой модели и поиска исторических закономерностей для российских акций. Система раскладывает рыночную цену на фундаментальную, событийную и фоновую составляющие, предоставляя доверительные интервалы для текущей и будущей динамики цен.

---

## 🚀 Возможности

- **📈 Рыночные данные в реальном времени и история** — MOEX ISS API (OHLCV для 5 тикеров: GAZP, SBER, LKOH, NVTK, VTBR)
- **💎 Фундаментальный анализ** — отчётность МСФО из PostgreSQL (BVPS, число Грэма, P/E, P/BV, ROE, чистая маржа)
- **🤖 ML‑прогноз цен** — гребневая регрессия (Ridge) с отдельными моделями для открытия, закрытия и внутридневной волатильности
- **🧠 LLM‑анализ новостей** — Qwen3.6‑35B классифицирует новости Smart‑Lab и оценивает их влияние на цену (в %)
- **📰 Автоматический сбор новостей** — Selenium‑сборщик для Smart‑Lab (последние 3 дня)
- **🔍 Поиск исторических аналогов** — косинусное сходство между эмбеддингами заголовков (multilingual‑e5‑large) для нахождения самых похожих дней
- **📊 Веб‑интерфейс** — приложение на Streamlit с интерактивными графиками, таблицами и элементами управления
- **⚙️ MLOps** — развёртывание через Docker Compose, мониторинг Prometheus + Grafana, отслеживание экспериментов в MLflow, ежедневное обновление данных по расписанию

## 🏗 Архитектура

**Локальный хост:**

- `llama-server` (GPU) на порту `:8001` — обслуживает LLM-модель
- `Docker Compose` — оркестрирует основные сервисы:
  - `Streamlit` (приложение) — `:8501`
  - `PostgreSQL` — `:5432`
  - `Prometheus` — `:9090` (профиль `monitoring`)
  - `Grafana` — `:3000` (профиль `monitoring`)
  - `MLflow` — `:5000`
  - Ежедневное обновление — `cron` на хосте

Приложение Streamlit обращается к `llama-server` для классификации новостей и создания эмбеддингов, к PostgreSQL за фундаментальными данными, и к MOEX ISS API за рыночными котировками.

## ⚙️ Требования

### Аппаратное обеспечение

- **GPU:** NVIDIA с 16+ ГБ видеопамяти (для Qwen3.6‑35B; часть слоёв можно выгрузить в RAM)
- **RAM:** от 32 ГБ рекомендуется
- **Диск:** ~30 ГБ для модели, данных и контейнеров

### Программное обеспечение

- **ОС:** Linux (Ubuntu 22.04+), Windows с WSL2
- **Docker** 24+ и **Docker Compose** v2+
- **NVIDIA Container Toolkit** (если GPU используется внутри Docker)
- **Python 3.12** (для локальных скриптов и LLM‑сервера)
- **CUDA 12.x** (для llama.cpp; избегайте версии 13.2!)

## 📦 Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/your-org/stock-analyzer.git
cd stock-analyzer
```

### 2. Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```env
DB_PASSWORD=ваш_надёжный_пароль
GRAFANA_PASSWORD=admin
```

> ⚠️ Добавьте `.env` в `.gitignore`!

### 3. Скачивание LLM‑модели

Поместите `Qwen3.6-35B-A3B-UD-Q3_K_M.gguf` в папку `models/`. Её можно получить с Hugging Face:

```bash
pip install huggingface_hub hf_transfer
hf download unsloth/Qwen3.6-35B-A3B-GGUF --include "*UD-Q3_K_M*" --local-dir models/
```

### 4. Сборка и запуск Docker‑сервисов

```bash
docker compose up -d
```

Будут запущены PostgreSQL, Streamlit, MLflow (и опционально Prometheus/Grafana).

### 5. Запуск LLM‑сервера (на хосте, вне Docker)

```bash
./llama.cpp/build/bin/llama-server \
  -m models/Qwen3.6-35B-A3B-UD-Q3_K_M.gguf \
  -ngl 30 \
  -c 8192 \
  --host 0.0.0.0 \
  --port 8001 \
  --chat-template-kwargs '{"enable_thinking":false}' \
  --embeddings
```

### 6. Загрузка финансовых данных в базу

Сначала получите фундаментальные данные из FinanceMarker API (опционально, если у вас уже есть JSON‑файлы):

```bash
python scripts/bd/fetch_company_data.py
```

Затем импортируйте все JSON‑отчёты в PostgreSQL:

```bash
python scripts/bd/load_to_db.py
```

### 7. Сборка ежедневных датасетов (необходимо для анализа и ML)

```bash
python scripts/build_company_datasets.py --all
```

### 8. Настройка ежедневного автоматического обновления (опционально)

Добавьте следующую строку в crontab хоста (`crontab -e`):

```text
0 23 * * * cd /путь/к/stock-analyzer && /путь/к/venv/bin/python scripts/daily_update.py >> logs/daily_update.log 2>&1
```

## 🖥 Использование

1. Откройте `http://localhost:8501` в браузере
2. Выберите тикер в боковой панели
3. Нажмите **«Загрузить данные MOEX и БД»**, чтобы получить рыночные котировки и фундаментальные отчёты
4. Изучите дашборд:
   - Текущие ценовые метрики
   - ML‑прогноз на следующий торговый день (открытие, закрытие, волатильность)
   - Таблица и графики фундаментального анализа
   - Сбор новостей и оценка влияния с помощью LLM
   - Исторические похожие дни (косинусное сходство)
5. Используйте кнопку **«Собрать новости Smart‑Lab»** для получения свежих статей (работает через Selenium внутри контейнера)
6. Нажмите **«LLM‑анализ»**, чтобы получить тональность и прогнозируемое влияние на цену для каждой новости

## 🔧 MLOps

### Docker Compose

Все сервисы (кроме LLM) работают в контейнерах, обеспечивая воспроизводимость и лёгкое развёртывание.

### Реестр моделей (MLflow)

Отслеживание экспериментов, логирование параметров и метрик, хранение артефактов моделей. Доступен по адресу `http://localhost:5000`.

```python
from scripts.mlops_metrics import log_model_metrics
log_model_metrics("GAZP", "Ridge", metrics, features, dataset_info)
```

### Мониторинг (Prometheus + Grafana)

Опционально — запускается с флагом `docker compose --profile monitoring up -d`.

- Prometheus собирает метрики node_exporter (ЦП, память, диск)
- Grafana визуализирует состояние системы

Учётные данные по умолчанию: `admin` / `пароль из .env`

### Обнаружение дрейфа данных

Функция `monitor_data_drift()` вычисляет индекс стабильности популяции (PSI) для обнаружения изменений в распределениях признаков.

### Непрерывное обучение

Ежедневная задача cron (или сервис daily-update) выполняет:
- Сбор новых заголовков Lenta.ru
- Классификацию через LLM
- Обновление эмбеддингов дней
- Пересборку датасетов компаний
